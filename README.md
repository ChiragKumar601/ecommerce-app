# Full Stack Ecommerce Application

## What I want to build?

I want to build a full stack application for the user side where users can come and check out some of the top fashion and beauty products for men, women and kids. I want it to have the feeling of a production-standard application.

## What problem I want to solve?

People are too lazy to go out shopping but they still want their appearance to be as good and stylish as possible. So, not only do I want a smooth user experience on the app, but I also want to bring the best items at the most affordable prices I can and, from the application perspective, improve the overall shopping experience.

## Who do I think will use it?

My customers will range from infants to old-aged people because I want to have fashion, beauty, lifestyle and other relevant products for everyone. I want to have products ranging from simple everyday fashion to cool and funky-looking products so that users can find whatever they are looking for.

I can imagine having a logo of my app at the top where, if someone clicks on the logo, I want them to be taken back to the landing page. The header will have different sections for Men, Women, Kids, Home, Beauty and something like Gen Z, as many of the customers will be interested in trend-driven products. The header will also have Search, Profile, Wishlist and Bag icons, and the section names should be shown below the icons.

The application should also have a simple and smooth account flow for users. Users should be able to browse products, categories and the landing page without being logged in, but actions such as placing an order, saving products to a wishlist, managing addresses or accessing profile information should require the user to log in or create an account. For now, login and signup should use an email address or phone number along with a password. Do not add OTP-based authentication for now. During account creation, the user should also set a security question and answer that can be used as an additional account recovery or verification step where required. Users should be able to log out, recover their account where applicable and handle expired sessions properly. If a guest user adds products to the bag or wishlist and later logs in, the application should handle the guest data properly instead of losing it, with the user's existing account data taking priority where there is a conflict. Protected pages such as Profile, Orders, Saved Addresses, Saved Cards, Wishlist and other account-related sections should only be accessible to the logged-in user. The application should show clear loading, validation, success and error messages throughout the authentication flow and should not expose account information belonging to another user.

The search experience should be an important part of the shopping experience rather than just a basic search input. Pressing Enter or selecting a suggestion should take the user to a search results page where they can use the same filters and sorting options available on category pages. Search results should support pagination or infinite scrolling, product counts, applied filter indicators, clearing filters and useful empty states when nothing matches the search. The search experience should work well on both desktop and mobile, with the search interface adapting appropriately to smaller screens. Search should also handle misspelled or slightly different search terms where possible so that users do not immediately get an empty page when a relevant product exists.

What is out of scope in v1 version?
For this version, the application will focus only on the main customer shopping experience. The admin or seller side of the application is out of scope, so product, inventory, order, user, and other management dashboards will not be built yet. OTP, phone verification, social login, and other login methods are also out of scope; users will only create accounts and log in using email and password, with a security question available for password recovery. Real payment processing and payment gateway integration are out of scope, so checkout will use a simulated payment flow. Native Android and iOS applications are out of scope, and the application will be built for the web only. AI-based assistance, AI shopping recommendations, AI search, virtual try-on, and other AI features are also out of scope. Live delivery-partner integration, real-time delivery tracking, multi-vendor or marketplace functionality, real-time customer support or chat, international shopping and multi-currency support, advanced loyalty and rewards systems, advanced analytics and reporting, marketing automation, and complex notification systems are also not part of this version. The goal of this version is to build the core customer journey of browsing products, searching and filtering, viewing products, managing wishlist and bag, adding an address, completing a simulated checkout, viewing orders, and handling basic cancellation, return, and refund flows. Anything outside this core customer shopping experience should be considered out of scope for this version.
